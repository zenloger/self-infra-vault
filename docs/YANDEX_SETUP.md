# Подключение Яндекс ID и Диска

Публичный адрес приложения: `https://secret.zenlog.pro`.
Для первого входа владелец должен зарегистрировать OAuth-приложение Яндекса
и указать его **ClientID** в конфигурации сервера. Мастер-пароль KDBX при этой
настройке не нужен. Не отправляйте пароли, токены, key files и client secret
в чат или Git.

## Регистрация приложения

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/) под аккаунтом владельца
   приложения и создайте новое приложение по
   [официальной инструкции](https://yandex.ru/dev/id/doc/ru/register-api).
2. Выберите платформу веб-сервиса. Укажите адрес сервиса
   `https://secret.zenlog.pro` и точный Redirect URI:

   ```text
   https://secret.zenlog.pro/auth/callback
   ```

3. В доступах добавьте следующие два права API Яндекс Диска:

   | Право | Идентификатор |
   | --- | --- |
   | Чтение всего Диска | `cloud_api:disk.read` |
   | Запись в любом месте на Диске | `cloud_api:disk.write` |

   Права email, телефона и профиля не нужны: стандартные поля идентичности
   возвращаются Яндекс ID и с токеном Диска. Доступ к папке приложения
   `cloud_api:disk.app_folder` не заменяет указанные права: база пользователя
   находится в обычной папке `/secret`.

4. Сохраните настройки приложения и скопируйте **ClientID**. Это публичный
   идентификатор приложения, а не OAuth access token. Если Яндекс показывает
   требования к регистрации или модерации, выполните их в кабинете владельца.

Приложение использует Authorization Code + PKCE `S256`. Текущая документация
Яндекса разрешает обмен кода с `code_verifier` без передачи client secret.
Поэтому для обычной настройки секрет приложения не требуется.

## Конфигурация сервера

Подключитесь к серверу обычным SSH и откройте файл конфигурации в редакторе:

```sh
ssh zenlog@zenlog.pro
sudoedit /etc/zenlog-vault.env
```

Заполните существующую переменную, заменив пример своим ClientID:

```dotenv
YANDEX_CLIENT_ID=replace_with_public_client_id
```

Не удаляйте остальные параметры, созданные установкой приложения.
Если владелец намеренно хочет дополнительно использовать секрет
конфиденциального OAuth-клиента, задайте в этом же файле
`YANDEX_CLIENT_SECRET`. Для PKCE-only оставьте её незаданной; не копируйте
секрет в команды shell, репозиторий или переписку.

Проверьте владельца/права файла и перезапустите сервис:

```sh
sudo chown root:root /etc/zenlog-vault.env
sudo chmod 600 /etc/zenlog-vault.env
sudo systemctl restart zenlog-vault
sudo systemctl is-active zenlog-vault
```

Изменение ClientID не требует пересборки браузерного клиента. После
перезапуска все прежние сессии завершатся: токены хранятся в памяти процесса.
Пустой ClientID оставляет вход через Яндекс недоступным до настройки.

## Первый вход и проверка

1. Откройте [secret.zenlog.pro](https://secret.zenlog.pro) и нажмите вход через
   Яндекс. Проверьте, что переход ведёт на `oauth.yandex.ru`, затем подтвердите
   доступ именно к созданному приложению.
2. После возврата на сайт должен отображаться ваш аккаунт и список
   непосредственных `.kdbx` из папки `/secret` в корне Диска. Создайте папку
   и положите туда базу KeePass, если она ещё не существует. Подпапки и файлы
   других форматов не входят в список.
3. Для первого теста используйте отдельную базу с вымышленной записью.
   Откройте её мастер-паролем в браузере, измените запись и сохраните.
4. Сохранение должно создать **новую версию `.kdbx`** в `/secret`, сохранив
   исходный файл. Проверьте открытие новой версии в KeePass. Автоматической
   перезаписи исходного файла и слияния с параллельными изменениями нет.
5. Выйдите из приложения. Для повторного доступа потребуется новый вход
   через Яндекс, а для открытия базы — её мастер-пароль.

Сессия длится максимум восемь часов. При отзыве токена или перезапуске сервера
нужно войти повторно. Выход удаляет серверную сессию, но не заменяет отзыв
разрешения в аккаунте Яндекса; при необходимости отзовите доступ приложения
там отдельно.

Ограничение `/secret` обеспечивает приложение. Запрашиваемые права Яндекса
позволяют токену читать и писать весь Диск; эта особенность показана явно,
потому что провайдер не предлагает scope для произвольной папки.
Остальные границы защиты описаны в [SECURITY.md](SECURITY.md).
